## 2026-09-21 高级树与 AVL 删除（当前有效状态）

本轮为红黑树、B 树、B+ 树补全删除操作，并把 AVL 从四类预制旋转升级为通用插入 + 删除引擎。实验总数仍为 6 章 54 个实验、11 类渲染器。

- **算法**：`assets/js/algorithms/advanced-trees.js` 三个生成器签名统一为 `(values, deletes, target)`；红黑树删除按 CLRS 处理「双黑」四情形（兄红 / 兄两孩子黑 / 远侄红 / 近侄红），B 树 t=2 删除先借位、后合并、根空降高，B+ 树删除后重算父索引（= 右子树最小值）并重接叶链 `next`。`assets/js/algorithms/search.js` 用 `avlTree(values, deletes, target)` 取代 `avlRotations`，删除按 BST 规则做中序后继替换后沿路径回溯，可能连续多次旋转。
- **输入**：三个实验与 AVL 都增加「删除序列」字段，可留空；序列中不存在的键不会报错，而是演示「未找到，跳过」。插入序列上限仍为 12 项。
- **快照约定**：删除请求即使被跳过也会产生 `deleted`/删除完成锚点，便于逐步校验；红黑树的双黑用哨兵结点表示，快照发出前必须已摘除哨兵与被删结点（否则会出现孤立结点）。
- **渲染**：`multi-tree-renderer.js` 显式绘制红黑树 NIL 空槽，并用双环 +「双黑」标出亏损结点；AVL 沿用 tree 渲染器的 `active` / `current` / `unbalanced` / `subtree` 标记。
- **测试**：新增 `tests/tree-invariants.cjs`（红黑树/B 树/B+ 树共用不变量校验）、`tests/advanced-tree-delete.test.js`、`tests/avl-tree.test.js`；`tests/advanced-trees.test.js` 与 `tests/expanded-algorithms.test.js` 随签名更新。Node 91/91 通过。
- **关键实现陷阱（勿重犯）**：① 删除修复的 far/near 侄子下标必须互为反向（`isLeft?1:0` / `isLeft?0:1` 不能写反）；② 快照是 JSON 深拷贝，`undefined` 会变成 `null`，B+ 的 `refresh` 必须过滤掉缺失的最小键；③ 任何结点摘除都要在 `emit` 之前完成。
- 产品边界更新：高级树已支持插入、删除与查找；AVL 为通用插入 + 删除，不再是四类预制旋转演示。

## 4. 当前接口与必须保留的约定

### 实验配置

`defineExperiment(config)` 目前要求：

| 字段 | 意义 |
| --- | --- |
| `id / chapter / title` | 唯一实验 ID、章节 ID、显示标题 |
| `visualizer` | `DS.Renderers` 中的类型名 |
| `tag / difficulty` | 标签与难度元数据 |
| `code` | 字符串数组；行号从 1 开始 |
| `generator` | 算法函数 |
| `preset` | 每次返回一份新的算法参数数组 |

当前 `createSteps()` 不接收自定义输入，只调用 `generator(...preset())`。实验对象和代码数组被冻结。新增输入能力时应修改统一接口，不能直接修改注册表对象。

### 运行器

当前使用 `DS.LabRuntime.createRuntime(elements)`，返回：

```js
runtime.mount(experiment); // 返回是否成功；当前会先销毁旧实验
runtime.destroy();
runtime.redraw();
```

注意：`subscribe()` 会同步触发首帧，因此首帧异常可能发生在取消订阅函数赋值之前。现有代码已处理这个情况，不要移除相关判断。

### 快照

算法通常返回以下形式的数组：

```js
{
  id: 'stable-step-id',
  line: 3,
  message: '本步操作说明',
  state: { kind: 'array', values: [3, 1, 2], active: [0, 1] }
}
```

运行器实际校验非空数组、有效 `line`、对象 `state`、非空 `message`。`id`、`kind`、`done` 是常用约定，不要误认为运行器已经强制校验它们。现有顺序表插入结尾也没有统一的 `done: true`；播放完成以快照索引到达末尾为准。

快照应使用 `structuredClone` 等方式隔离可变状态。不要用 JSON 序列化复制距离表，`Infinity` 会被转换成 `null`。

### 当前图/树模型

```js
// 边数组中的第三项是权值，坐标归一化。
{ directed: true, nodes: [{id: 'A', x: 0.2, y: 0.5}], edges: [] }

// 二叉树以节点 ID 关联，不以显示标签作为主键。
{ root: 'A', nodes: {A: [null, null]}, labels: {A: '12'} }
```


### 5A-4. 后续参数接入顺序与陷阱

| 接入项 | 当前算法约定/所需修正 |
| --- | --- |
| 顺序表插入 | `sequenceInsert(input, index, value)` 的预设数组含末尾 `null` 空槽；UI 不应要求用户手填 null。适配层补容量空槽，明确 0-based 下标或 1-based 位置后转换 |
| 链表逆置 | 接收数值数组；节点 ID 应与值分离，重复值仍是不同节点 |
| Huffman 权值 | 非空正权值，至少验证单元素；现实现空数组会访问缺失根节点。初期建议限制 2–8 个权值 |
| 哈希表 | 当前 `value % size` 对负数产生负下标。开放负值前改为 `((value % size) + size) % size`；表长必须是正整数 |
| BST | 当前相同值插到右子树；须保留并说明重复值策略，限制输入规模，检查极端单链树布局 |
| AVL | 当前仅四种预制旋转，不是任意插入平衡树。不能只给现有演示增加输入框并声称支持任意 AVL 插入 |

## 7. 第三阶段：图编辑与拖动（任务 5C–5D）

### 5C-0. 先修算法输入边界，再开放编辑器

以下是接手时从源码确认的现状，原预设测试通过不表示已经支持任意图：

| 位置 | 当前行为 | 开放输入前必须做的事 |
| --- | --- | --- |
| `graph.js / adjacency` | 总是添加双向邻接，未按 directed 区分 | BFS、DFS、Dijkstra 需要遵守图方向 |
| `graph.js / floyd` | 初始化时总是对称赋权 | 有向图只写正向；无向图再写反向 |
| `graph.js / prim` | 断连后提前退出，却仍宣称得到最小生成树 | 首版可拒绝非连通输入，或明确返回仅起点分量的树；不得假称全图 MST |
| `graph.js / kruskal` | 结束文案固定“已选 n-1 条边” | 断连时明确返回最小生成森林，或与产品约定一致地拒绝输入 |
| `graph.js / topological` | 不检查输出数是否等于顶点数 | 有环时返回失败状态，不能宣称完整拓扑序 |
| `graph.js / criticalPath` | 直接使用拓扑输出，未验证 DAG | 先验证无环；事件时序必须完整 |
| Dijkstra | 未显式拒绝负权 | 在实验约束和算法入口均保护非负权要求 |

建议先用纯 Node 测试覆盖有向边、断连、孤点、负权、环和无效起点，再接 UI。算法函数自身也应校验其关键前置条件，不能完全依赖表单。

### 5C-1. 图编辑器最小版本

建议新增 `assets/js/core/graph-input.js` 和 `assets/js/ui/graph-editor.js`。

第一版采用“节点清单 + 边清单 + 权值 + 起点 + 方向”的可访问表单。Canvas 点击建点、连线手势可以后续再加，不影响第一版交付。

建议限制 2–10 个节点、最多 20 条边，节点 ID 使用 A–Z 单字母，权值范围 `[-99, 99]` 内整数；具体实验再收紧。例如 Dijkstra 拒绝负权，AOE 使用非负工期，MST 只接受无向图。首版拒绝自环和重边，节点 ID 不重复，边端点必须存在，起点必须属于节点集。零权边必须被正确保留。

有向图的 A→B 与 B→A 不是同一条边；无向图应将其视为重边。若支持双向有向边，绘图必须区分两条边的方向与权值，不能让箭头和标签完全重合；未实现该画法前应明确限制而非静默画错。

编辑器维护独立草稿。删除节点时同步删除相关边，并提示起点失效。点击“应用图”才重新生成快照；草稿非法不影响当前播放案例。默认位置使用确定性圆周布局，刷新/重复应用同一输入不会随机改变布局。

算法专属策略写在实验配置附近，避免在编辑器内部堆积 `if (id === ...)`。

### 5C-2. 验收案例

- 有向链 A→B→C，从 C 开始 BFS/DFS 只能访问 C；不能反向遍历到 A。
- 无向非连通图的 Prim/Kruskal 按声明策略拒绝或显示部分树/森林。
- A→B→A 的拓扑排序明确报环；关键路径不生成成功结果。
- Dijkstra 拒绝负边；允许零权边；不可达顶点保持 Infinity。
- 删除起点、删除被引用节点、重复 ID、无效端点均有明确反馈。
- 新增/删边之后应用、重置、返回首页、重进实验均无旧事件/计时器。

### 5D. 图节点拖动

在图编辑稳定之后实施。把节点坐标作为展示布局状态保存，与算法快照的结构/权值分开；不能为了移动节点逐份改写历史快照。

建议为渲染器增加可选第三参数 `{ layout }`，由运行器统一在 sync/redraw 中传递；其余 renderer 可以忽略它。拖动只改布局并重绘，不重新运行算法、不改游标，也不改变最短路径或 MST 结果。

CanvasScene 在窄屏中使用虚拟 420px 场景宽度，bitmap 又受 DPR 影响。请集中实现坐标转换/命中测试工具，不能直接用 `offsetX * devicePixelRatio` 当算法坐标。当前图节点按归一化比例绘制；指针归一化可从 `(clientX - rect.left) / rect.width` 等计算，命中半径还需对应虚拟场景缩放。

使用 Pointer Events 和 pointer capture，处理 `pointerup`、`pointercancel`、丢失捕获、路由销毁；将节点中心限制在带半径边距的可视范围。开始拖动时暂停播放，松开后保持暂停。提供键盘或表单调整坐标的等价方式。

验收：鼠标与触屏；DPR 1/2；320/390/1440px；拖动后换主题、缩放、上一步/下一步仍保持布局；拖动中离开实验无残留监听；原快照和算法结果不变。
