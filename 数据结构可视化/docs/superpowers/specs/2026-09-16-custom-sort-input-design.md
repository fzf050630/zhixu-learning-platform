# 任务 5A：排序实验自定义输入设计

## 目标

为快速排序、堆排序、直接插入排序和归并排序增加安全、可复用的自定义整数数组输入。输入错误时保留当前已应用案例和播放进度；输入成功后生成新的完整快照并从第一步暂停。折半查找输入暂不在本阶段接入。

## 已确认约束

- 页面继续使用 HTML/CSS/原生 JavaScript + Canvas 2D，可直接通过 `file://` 打开。
- 算法仍然一次生成完整快照，播放器只消费快照；渲染器不重新推演算法。
- 输入限制统一为 1–12 个整数，每项 `[-999, 999]`；分隔符支持英文逗号、中文逗号和空白。
- 允许重复值；拒绝空内容、非整数、小数、NaN/Infinity、超长数组和越界整数。
- 应用成功、恢复预设和重置都不启动自动播放。
- 应用失败不销毁当前播放器、不清空画布、不显示“算法崩溃”；字段旁显示明确错误。
- 自定义输入通过 `textContent` 或安全 DOM API 写入页面。
- 不能修改同级“概率论可视化”项目；开发依赖不进入运行页面。

## 备选方案

1. 在 `app.js` 中为四个实验分别写输入解析和按钮分支。实现最快，但会把算法参数、表单生命周期和路由逻辑耦合在一起，后续折半查找和图编辑会继续复制分支。
2. 由实验配置声明输入能力，使用纯 `input-validation.js` 解析校验、`experiment-input.js` 管理表单、`LabRuntime` 统一生成候选快照并替换播放器。新增实验只需声明配置，生命周期和错误行为集中管理。此方案为本阶段推荐方案。
3. 让每个算法自带输入表单和播放器。算法可以完全自包含，但会破坏统一运行器约定，容易产生重复监听器和不同的错误/重置语义。

## 架构与接口

### 输入校验

新增 `assets/js/core/input-validation.js`，采用 UMD/CommonJS 包装，页面和 Node 测试都可加载。导出统一常量和 `parseIntegerArray(raw, options)`：成功返回新的整数数组，失败返回包含 `ok: false`、`message` 和必要错误信息的结果，不抛出用户输入错误。默认限制集中在模块常量中，具体实验可以通过 options 收紧但排序使用默认值。

解析规则为：去除首尾空白；以逗号或任意空白分隔；拒绝空 token、非十进制整数 token、超出范围的整数；再校验数组长度。解析结果与原始输入隔离，外部修改不会影响后续快照。

### 实验配置

扩展 `defineExperiment(config)` 的可选输入描述，例如：

```js
input: {
  type: "integer-array",
  label: "待排序数组",
  placeholder: "例如：49, 38, 65, 12",
  defaultValue: "49, 38, 65, 12, 27, 81, 55",
  parse(raw) { return parseIntegerArray(raw); },
  toArgs(values) { return [values]; }
}
```

实验对象保留新的 `createSteps(normalizedInput)` 能力：无输入时使用冻结配置之外的全新 `preset()` 参数；有输入时调用配置的适配器生成算法参数。输入描述与实验对象一起冻结，默认字符串和数组均需复制，避免草稿或算法修改配置。

### 运行器与播放器

`LabRuntime.mount(experiment, options)` 接受可选 `{ input }`。运行器先调用 `experiment.createSteps(input)` 并验证快照；候选步骤成功后才销毁旧播放器并安装新播放器。失败时保留旧播放器、旧代码高亮、画布和游标，向输入 UI 返回错误而不是进入全局实验失败态。为保持旧调用兼容，未声明输入的实验仍按当前 `mount(experiment)` 行为工作。

成功替换时重新渲染代码、重建播放器、首帧暂停显示；`reset()` 只重置当前已应用的步骤，因此自定义案例不会被默认预设覆盖。旧播放器的定时器、订阅和输入相关监听器必须在替换时释放。

### 输入 UI

新增 `assets/js/ui/experiment-input.js`，提供 `createExperimentInput(container, experiment, callbacks)`，负责创建/更新表单、显示字段错误、应用输入和恢复预设按钮，并返回销毁函数。UI 不直接调用播放器或 Canvas；回调由 `app.js` 将标准输入交给运行器。

实验路由进入时，只对声明 `input` 的实验显示参数区域；离开实验或切换实验时销毁旧 UI。编辑草稿不会改变已应用输入，恢复预设将草稿替换为默认文本并立即应用默认案例。

## 数据流

```text
草稿文本
  → experiment-input 提交
  → input-validation 解析/校验
  → 标准整数数组
  → experiment.createSteps(input)
  → LabRuntime.validateSteps
  → 成功后销毁旧播放器并安装新播放器
  → Canvas、伪代码、说明和控制器同步到第 1 步
```

非法输入在解析或候选快照阶段失败时，不进入替换步骤。算法/渲染器真正抛出的运行异常仍使用现有全局错误恢复逻辑。

## 测试设计

- `tests/input-validation.test.js` 覆盖英文逗号、中文逗号、空白、负数、重复值、空输入、非法字符、小数、NaN/Infinity、长度和数值边界，并确认结果隔离。
- `tests/experiment.test.js` 或现有实验测试覆盖 `createSteps(input)` 参数适配、默认 preset 隔离和输入配置冻结。
- `tests/runtime.test.js` 覆盖候选步骤成功后替换、候选输入失败后旧播放器和游标保留、重复应用不叠加控制监听。
- `tests/browser/lab.spec.js` 增加四种排序逐一应用 `3, -1, 3, 0`，确认末帧为 `[-1, 0, 3, 3]`；覆盖恢复预设、非法输入保留案例、重置自定义案例、播放中应用新案例后旧计时器停止，以及小屏/键盘输入不被全局快捷键抢占。
- 保留并重跑已有 Node 和 Chrome 测试；浏览器测试继续从本地 `file://` 加载并检查无页面错误、无远程请求。

## 阶段边界

本设计只覆盖四种排序的整数数组输入。折半查找的数组和目标值、状态表、图编辑器、图节点拖动及新算法留到后续阶段，不在本次实现中提前接入。
