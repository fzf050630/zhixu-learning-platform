# 408 与考研数学交互学习平台：首期框架方案

日期：2026-09-17。状态：用户已批准，首期框架已实施；验证结果见 ../../verification/platform/VERIFICATION.md。服务器远程上线不在已完成状态内。

## 目标与本次范围

建设可部署到个人服务器的统一学习平台，覆盖 408 四科和数学三科。本次交付统一门户、导航、视觉规范、现有两个学科接入、发布工具与部署说明。其他五科仅登记入口和“待建设”状态，不新增课程、实验、模拟数据或虚构进度。

数学三科按高等数学、线性代数、概率论与数理统计组织；当前概率论内容保留“数学（一）· 2026 大纲”的来源标注，数据结构保留现有复习范围标注，不把现有内容描述为七科全部完成。

## 已检查的项目事实

- 数据结构：原生 HTML/CSS/JavaScript；注册表、算法、播放器、渲染器已经分离；现有交接文档记录 6 章、35 实验、11 类渲染器。文档记录 Node 61/61、Chrome 23/23 通过，这是历史结果，本轮尚未复跑。
- 概率论：原生 HTML/CSS/JavaScript，8 章内容文件；README 记录 44 小节、60+ 交互组件，接入时从内容注册数据生成实际目录和数量。KaTeX、字体均在本地。
- 两者均使用 hash 路由、Canvas 图示、CSS 变量和浏览器本地存储；现有主题键分别是 ds-theme 和 kaoyan-prob-theme。
- 概率论学习进度使用 kaoyan-prob-progress-v1。保留该数据，不把数据结构的访问记录当作“已掌握”。
- 根目录不是 Git 仓库；实施前建立针对被修改文件的备份清单，不假定可用 Git 回滚。

## 方案比较与选择

1. **推荐：静态多页面平台，共享界面层。** 新门户与学科页使用相同品牌、科目切换器、主题和基础控件。各学科保留独立的运行环境与 hash 路由，以常规页面导航切换。复用现有代码，适合本次范围，服务器只需提供静态文件。
2. iframe 总外壳。初期接入快，但会增加双重滚动、打印、键盘焦点、地址与主题同步的处理成本，不作为首选。
3. 全量迁移到 React/Vue 单页应用。长期适合复杂账户与协作产品，但需要同时改写两套成熟页面的生命周期与渲染接入，超出本次框架建设范围。

推荐方案中的统一框架不仅是两个外链：学科页也必须具备统一导航、主题和控件视觉；学习内容区维持各学科需要的布局。

## 信息架构与页面

平台暂名“知序 · 交互学习”，作为集中配置项，后续可以直接更换。

```text
平台总览
├─ 408 计算机基础
│  ├─ 数据结构                 接入现有项目
│  ├─ 计算机组成原理           待建设
│  ├─ 操作系统                 待建设
│  └─ 计算机网络               待建设
└─ 考研数学
   ├─ 高等数学                 待建设
   ├─ 线性代数                 待建设
   └─ 概率论与数理统计         接入现有项目
```

总览包含平台标题、按上述两组排列的科目入口、现有内容搜索与最近访问入口。可用科目明确显示内容范围和进入按钮；未建设科目显示状态，不提供失效的“开始学习”按钮。只搜索现有章节、知识点与实验标题，不承诺教材全文搜索。

学科页顶部共享平台品牌、返回总览、学科切换与主题控制；本学科侧栏继续承载章节和实验目录。避免同时排列两套完整侧栏。桌面保持图形操作空间，手机将目录折叠，控件和表格在各自区域滚动。

## 统一视觉

基于已有米白底、蓝色强调色，统一为清晰的学习工作台：低饱和背景、白色内容面、清晰边界，保留深色模式。共享中文系统字体栈、正文层级、间距、圆角、按钮、搜索框、焦点环和状态色。正文以可读性为先，避免沿用部分现有 10–11px 的主要操作文字。

建立共享 CSS tokens，并为两套旧变量命名提供映射，减少大范围替换。保留图中代表不同节点、概率事件与统计含义的语义颜色。主题切换同时更新 Canvas，不能仅改变页面背景。

## 工程与接口边界

```text
index.html                    平台总览
platform/
  subjects.js                  七科登记：id、分组、标题、状态、入口
  catalog.js                   从现有内容生成的可搜索目录
  theme.js                     平台主题与旧主题偏好兼容
  navigation.js                共享科目切换、返回、最近访问
  portal.js                    总览页面交互
  tokens.css                   共享颜色、字体、间距、圆角
  components.css               共享界面控件
  adapters.css                 学科旧样式适配
数据结构可视化/                 保留现有源码目录
概率论可视化/                   保留现有源码目录
scripts/                       静态发布与目录生成
deploy/                        Nginx / Docker 配置
dist/                          生成的服务器发布文件
docs/                          接入约定、验收记录、部署说明
```

发布脚本将两个源码目录映射到 dist/subjects/data-structures/ 与 dist/subjects/probability/。资源与导航使用可支持子路径部署的相对地址。构建不更改章节与实验 hash 标识，支持直接打开具体知识点、刷新与浏览器前进后退。

subjects.js 是科目元数据的唯一来源。搜索目录从现有注册数据生成，避免复制维护整套课程内容；结果包含科目和具体章节/实验，点击直达。新科目按登记、接入共享界面、生成目录、验证四步扩展。

## 本地状态与兼容

统一主题键为平台级命名；首次接入优先采用平台设置，尚无平台设置时兼容当前学科旧主题设置。两学科主题按钮调用同一主题接口并触发各自图形重绘。存储被禁用或内容损坏时回退到可用默认状态。

最近访问仅保存受控的科目 ID 与内部路由，恢复前校验仍在目录中。保留原概率论掌握标记；本期不引入统一掌握率，不虚构数据结构学习进度。

浏览器存储按来源隔离：从 file:// 或 localhost 移到服务器域名后，原本地进度不会自动迁移。服务器部署不代表跨设备同步，本期不引入账号或数据库。

## 服务器交付

提供两条交付路径：上传 dist 到已有 Nginx 静态站点；或者使用 Docker Compose 启动静态站点容器。具体端口可配置，支持域名根路径和子目录部署。HTTPS 接入现有反向代理，并在文档中说明需要替换的域名和证书位置。

发布采用文件白名单，只包含 HTML、必要脚本、样式、字体和公式资源。不发布教材 PDF、node_modules、备份、临时文件、测试截图和开发文档。未接收到服务器连接信息时交付可部署文件和操作文档，不宣称已完成远程上线。

## 实施顺序

1. 保存变更前的入口、样式与应用脚本备份；复核现有目录和路由。
2. 建立科目登记、共享主题与控件规范，制作总览。
3. 接入两学科的导航、主题与样式，保留原有交互功能。
4. 生成真实搜索目录和最近访问，处理空状态及无效地址。
5. 增加白名单发布、Nginx 和 Docker 配置、部署及扩展文档。
6. 对源码预览和发布产物进行验证，修复集成问题后交付截图与启动方式。

## 验收条件

- 总览有七科，只有现有两科开放；其余科目明确标识待建设。
- 两个项目进入后有统一平台导航，可相互切换并返回总览。
- 搜索命中真实内容并能直达；无结果时提供明确反馈。
- 深浅主题在总览和两科间保持一致，Canvas 跟随重绘。
- 数据结构原有 Node 和浏览器回归通过；概率论验证章节跳转、公式渲染、参数交互、掌握标记及打印布局。
- 新增集成浏览器检查覆盖两科导航、返回/刷新、主题持久化、搜索直达、320/390/1440px 布局、控制台错误和静态资源 404。
- 发布产物单独启动后可使用；验证根目录及子目录资源路径，检查发布白名单。
- 若本机无 Docker，仅能记录容器配置检查和静态产物验证结果，不能宣称容器启动已验证。
