## 本轮重点验证

1. **页表不取模。** 执行真实`virtualMem`函数：初值虚拟地址0x1A2C转换到0x9A2C；VPN=4显示未驻留并提示调页；VPN=10且偏移7显示“未列出/无法由当前页表确定”，不会错误复用VPN=0的页框5。由于演示只列出部分页表，未列出不能直接断言真实地址非法或一定缺页。
2. **CLOCK不承诺消除Belady。** 实际widget说明只保证严格LRU具有栈性质。向真实模拟输入`1,2,3,4,1,2,5,1,2,3,4,5`，CLOCK在3行时9次缺失，在4行时10次缺失，构成当前实现下的直接反例。
3. **Cache tag。** 同一32位地址、4KiB数据容量、16B块，直接映射tag20位，全相联28位，4路组相联22位；全相联省去索引而不是省去tag。另独立核算24位地址、4KiB/32B/2路算例：每行附加LRU秩位时34816bit，改用每组1位替换信息时34752bit，二者存储组织不同。
4. **64B总线例题。** 32bit即每数据拍4B，需16数据拍；每事务限4数据拍，故4事务各付1地址拍，总20拍。200MHz下100ns，有效640MB/s；17拍仅适用于同一事务允许16个数据拍的不同题设。核对了运行后的原例题答案和补充正文，二者一致。

## 本轮新增修复

**Cache参数产生小数位宽。** 原`cacheMapping`滑杆可选3KiB、12B块、6路等参数，直接代入log2，实测3KiB产生`tag=22.415037499278846位`。图示采用连续二进制位段模型，这些输入不适用。滑杆改为指数索引，显示实际的1/2/4…KiB、4/8/16/32/64B、2/4/8/16路，并新增模型边界说明；最小1KiB与最大64B/16路组合仍合法。验证脚本遍历各控件可选值，检查位宽、组号和总行数均为整数。

**磁盘容量标签。** `diskAccess`按记录面×磁道×扇区×512B有效数据计算，却标为非格式化容量。PDF第115页（印刷103页）的扫描图与OCR均明确该乘积为格式化容量。已修正widget标签，与补充层原有容量表一致，不改变计算数值。
